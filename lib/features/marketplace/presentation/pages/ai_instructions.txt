FamHub AI Instructions Summary (v1.0 — Updated)
Core Identity
Project: Famhub - AgriTech Flutter app for Farmers & Agricultural Buyers
Stack: Flutter (Dart), Supabase (PostgreSQL), Riverpod v2.x, GoRouter
Key Focus: Rural accessibility, low-data usage, offline-first, security via RLS

🎯 Strategic Principles
Goal	Implementation
Performance	Low-data usage for rural areas
Security	Supabase RLS mandatory (users see only their data)
Offline First	CacheService with background sync
Architecture	Modular, multi-platform, self-registering

📁 Project Structure

lib/
├── main.dart (minimal entry point)
├── core/ (Providers, Services, Theme, Shell)
├── shared/ (Shared widgets, layouts)
├── features/module_name/ (self-contained modules)
└── system/ (Module registries, contracts)
🚫 Critical Rules
NO-SCAFFOLD RULE: Modules MUST NOT contain Scaffold, AppBar, or BottomNavigationBar.
NO UI IN MODULE CONTRACT: AppModule is metadata-only (no build()).
NO GoRouter IN FEATURES: All routing defined in core/router/app_router.dart.
NO setState IN PAGES: Use Riverpod providers for state management.

📤 Module Registration Checklist (v1.0)
✔ Generate full folder structure in features/
✔ Provide Provider (Riverpod) + Repository (Data) + View (Responsive)
✔ Register in system/registry/module_registry.dart (ModuleDefinition)
✔ Route registered in system/registry/route_registry.dart (RouteMapping)
✔ Feature flags in system/registry/feature_registry.dart (FeatureDefinition)
✔ Access rules in system/registry/access_registry.dart (AccessRule)
✔ Dependencies in system/registry/dependency_registry.dart (DependencyEdge)
✔ AppModule contract: features/<module>/module/<module>_module.dart
🔄 Data Flow
UI (ConsumerWidget) → Provider (Riverpod) → Repository (Backend) → Supabase (RLS)
